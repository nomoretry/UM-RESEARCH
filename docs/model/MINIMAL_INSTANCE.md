# 新建固定设施连续 SOC 最小验证实例

本实现于 2026-11-04 新建，不是找回的 `truck_charging_v1`。它实现 [FORMULATION](FORMULATION.md) 的固定设施首步；接口数量、站点启用和容量都是输入，投资变量尚未释放。

## 输入及边界

输入：[minimal_three_trucks.json](../../configs/minimal_three_trucks.json)。所有物理参数为明确的假设，任务时间轴为模拟；没有观测数据。所有零耗能槽都是本实例明确设计的非驾驶槽，不能把真实数据缺口填零后使用。

- 3 辆车、2 个站点、4 个完整的一小时时槽：驾驶、充电、驾驶、充电。V1/V2 只能在 A 站充电，V3 只能在 B 站充电。
- 每车初始和最大电量均为 100 kWh，最低电量 20 kWh；每段驾驶耗能 30 kWh，电网到电池效率 0.9，单车/独立接口的共同上限 50 kW。
- A 站有 2 个接口、100 kW 可用接入功率；B 站有 1 个接口、50 kW。功率已经是分配给车队的可用上限，不再扣除背景负荷。
- 两个充电槽电价分别为 1、2 模拟货币/kWh。`representative_weight=1`，只算此四小时封闭周期，不代表 24 小时运营日或全年。
- 初值使用满电；期末要求恢复到初值。因此充电需要来自已模拟的任务耗能，不来自人为降低初始 SOC。
- 允许在不同完整槽重新连接；不含“一次停车只能连续接枪一次”约束。没有槽内接口轮换、局部时槽插枪、共享功率柜、路由或跨站移动决策。

`charging_site` 每槽只能给一个精确站点 ID 或 `null`，表示该槽完整可充电的位置。行驶耗能大于零时必须为 `null`。这是给定的运输时间轴，不是路线可行性证明或真实窗口识别算法。`power_limit_kw` 必须逐站明确给出；没有默认值或键名猜测。

`--suite` 仅接受上述精确物理实例（逐项核验时间、车辆、能量、窗口、站点设施和价格），不能给任意同名站点/车辆输入套用本表的场景变换。其他合规输入应省略 `--suite` 作为单实例运行。JSON 重复键会被拒绝，不使用最后一个值悄悄覆盖前值。

## 可手算的验收值（运行前的数学预期）

基准每车净需补回 60 kWh 电池能量，需电网电量 `60 / 0.9 = 66.6667 kWh`。第一段驾驶后只有 30 kWh 电池空间，因此低价窗口至多补 30 kWh；剩余 30 kWh 必须在高价窗口补回。三车费用下界与可行解均为 `3 × (30 / 0.9 × 1 + 30 / 0.9 × 2) = 300`。总电网电量 200 kWh，各车电量轨迹为 `[100,70,100,70,100]`。

| 情景 | 相对基准的明确变更 | 解析预期及理由 |
|---|---|---|
| base | 无 | 最优费用 300；A/B 峰值分别 66.6667/33.3333 kW |
| interface_bottleneck | A 接口数降至 1 | 不可行；两窗最多 `1×50×2=100` kWh 电网电量，小于 A 两车所需 `120/0.9=133.3333` |
| power_bottleneck | A 可用功率降至 60 kW | 不可行；两窗最多 120 kWh，小于 133.3333 |
| window_bottleneck | V3 末窗关闭 | 不可行；V3 第一窗电池空间仅 30 kWh，无法补齐两次驾驶共 60 kWh |
| higher_power_no_benefit | A 可用功率增至 150 kW | 最优费用仍为 300；电池空间和相同任务下没有可降低的费用 |
| zero_demand | 所有驾驶耗能明确改为零 | 最优电网电量和费用均为零；不制造充电需求 |

上表是解析验收标准；实际执行状态和数值必须引用独立 run/result，不能只凭表格声称已求解。不可行情景由求解器状态与上述必要条件分别支持；没有原始可行解时，独立原始解检查标为不适用，不填“通过”。

## 实现与复核

- [model.py](../../src/um_charging/model.py)：`validate_input` 严格检查字段、单位、维度、有限性、站点位置与行驶互斥；`solve` 构建二进制接口占用、连续充电功率、跨两个任务连续传递的电池能量。
- [validation.py](../../src/um_charging/validation.py)：直接读取原始解，逐车积分电量并检查电量界、期末补回、占用整数性、窗口、单车功率、接口并发、站点总功率和费用；不读取求解器约束矩阵或残差，也不先把原始占用值取整。
- [test_fixed_facility.py](../../tests/test_fixed_facility.py)：手算目标/电量对照、三类已知无解、零收益与零需求、能量欠账/下界/关闭站点，以及对独立校验器的电量、占用、接口、功率、费用篡改反例。
- C01 固定设施：`active`、`interfaces`、`available_power_kw` 都是输入；尚未验证新增接口与离散扩容投资。投资费用作为固定沉没成本省略。

## 重跑命令

先提交精确源码，在主仓库外建立无 remote 的独立普通 Git。输出位置须是其下尚不存在的新目录；CLI 会拒绝仓库内输出、有 remote 的日志库、脏源码或覆盖已有 run。

```powershell
$env:PYTHONPATH = (Resolve-Path .\src).Path
python -m um_charging --config configs/minimal_three_trucks.json --suite --output <外部本地Git中的新目录>
python -m pytest -q -p no:cacheprovider tests
```

Python 3.12 环境依赖见 [requirements-milp.txt](../../requirements-milp.txt)。调用方必须按 [STORAGE](../workflow/STORAGE.md) 捕获 stdout/stderr/退出码；求解器版本在本地 stdout 的 HiGHS banner 中。CLI 保存精确配置、原始解、独立验证、输入/源码 hash、source commit、环境与终止状态；精选结果须从实际 run 提取。
