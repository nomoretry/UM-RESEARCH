# 保存、恢复与结果发布

## 两个独立仓库

1. UM-RESEARCH：现有 GitHub 私有仓库的本地克隆，管理源码、模型、研究状态、配置与精选结果。
2. UM-RESEARCH-runs-local：位于主仓库外、仅在实际运行机器初始化的独立 Git 仓库，无 remote，保存完整运行记录。

本地Git不是云备份；本地日志应另做用户控制的离线备份。云端Codex或另一台电脑不会自动获得这些日志，续接时使用主仓库内的状态与结果清单。

## 初始化（须在用户实际运行机器执行）

在与主仓库并列的新空目录初始化运行仓库。以下命令为操作示例，本次没有在用户电脑执行：

~~~bash
git init UM-RESEARCH-runs-local
git -C UM-RESEARCH-runs-local remote -v
~~~

第二条输出应为空。确保目标不在主仓库内，也不是其submodule/worktree；不要添加任何远程地址。
每次运行前再次检查 remote；可加拒绝所有push的pre-push钩子作为额外防误操作措施，但钩子可被绕过，不是隔离的替代。

只在确认日志不含凭据后，按实际run_id显式添加并提交，不使用全目录盲目add。不要为提交而临时伪造Git作者身份。
运行大文件可本地压缩并评估空间；Git不适合高频大型二进制增量。

## 完整本地运行包

每个 run_id 使用独立目录，至少包含：
- manifest.json：UTC时间、任务、源码commit、是否dirty、配置/数据hash、种子、环境与求解器版本。
- command.json：实际命令及必要的非敏感参数；不记录密钥或完整环境变量。
- stdout/stderr、退出码、求解器日志、模型导出（若支持）、原始解、诊断报告。
- dirty源码patch和未跟踪必要源码快照（若存在）；无敏感内容。
- 本次失败的原因、已知限制及重跑条件。
不要覆盖旧run，失败也保留。

## GitHub 精选结果包

主仓库 results/<experiment_id>/ 在真实实验后创建，包括：
- README.md：问题、对照、数据范围、结论、失败样本与局限。
- metrics.csv/json、图表、足以核验结论的精简逐实例结果。
- reproduction.json：源码commit、配置/数据hash、随机种子、环境/求解器、执行命令、对应run_id与本地证据包摘要hash。
- 配置、数据获取/生成方法和有授权的最小输入；无法共享输入时直说外部复现限制。
- validation.json：可行性残差汇总、求解状态、objective、bound、gap及单位；非适用字段用null并说明。

只有hash不能证明数值正确，也不能让他人重建不可用数据。原始日志不上传时，应明确外部可复现程度。
使用精确源码提交进行正式重跑；结果提交晚于源码提交是正常的，不以结果提交作为产生结果的源码版本。
结果默认经本地Git提交再push；“结果放GitHub”并不意味着它绕过本地Git。

## 上传边界

.gitignore 仅影响未跟踪文件，不从Git历史删除旧内容。不得用skip-worktree或assume-unchanged当保密机制。
也不得先把日志提交进主分支，再删掉文件后推送；可达的历史仍会上传。
不要使用push --all或--mirror；推送明确的研究分支。
现有raw/processed和PDF保留，不在本次恢复中重写历史或改变可见性。新增来源先记录使用/再分发条件。

## 每次工作收尾

1. 核实结果与运行记录成功保存；检查失败时如实记录。
2. 更新STATUS的可验证进展与下一任务，实质决策追加DECISIONS。
3. 按公式编号更新IMPLEMENTATION_MAP。
4. 主仓库只提交明确路径；检查差异中没有运行日志或无关个人记录。
5. 在已授权范围内推送研究分支；仅上传新的有效证据，不声称后台持续运行。
