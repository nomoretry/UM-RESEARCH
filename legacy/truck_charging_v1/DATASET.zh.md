# 数据集构建说明

## 一、数据分层

| 层次 | 本次内容 | 能支持什么 |
|---|---|---|
| 原始资料审计 | 原有parquet为403错误页，已拒绝 | 证明当前不能使用该文件，不能据此判断真实站点数量 |
| 文献参考 | `data/reference/literature_parameters.json` | 查出处、理解假设；不能直接充当2026广东实测参数 |
| 模拟数据 | `data/synthetic/demo.json` | 验证程序、单位和模型约束 |
| 真实资料采集 | `data/collection/intake_template.json` | 记录资料与证据；目前表为空，不是已建成数据库 |
| 模型结果 | `results/` | 对对应输入的求解与校验，不能反过来当原始数据 |

首版使用JSON而不是手工维护Excel公式，便于程序严格检查字段、记录版本并重复运行。数据字典中的字段是本项目新设计的接口，不是猜测外部数据库的实际字段。拿到新文件后先读真实schema，再建立明确映射。

## 二、哪些数据必须取得

### 1. 节点与路网

物流节点应当是有出处的实际设施及其出入口，不是城市中心点或注册地址的随意替代。

需要记录：设施名称、所属城市、来源、原始坐标及坐标系、核实后的进出口、连接道路、核实日期。路段需要有向连接、距离、时间和通行适用条件。V1输入边不能存在重名或平行边；若真实道路有多条平行连接，需先保留区别并构造中间节点，不能无提示删除。

坐标不得直接混用GCJ-02与WGS84。只有道路连通不足以证明重卡可通行；开放地图没有限行记录也不能视为无任何限制。官方通告还需核对车辆类型、生效日期及时间窗。

### 2. 场站信息

需要核实：是否允许目标重卡进入与停靠、实际入口及出口方向、开放时间、能否建设或扩建、可配置充电位数量的依据、兼容设备功率、可用容量。

主模型只接受已明确的可选建设位置。没有建设许可资料时只能建立假想建设情景，并在证据中注明，不能声称现实可获批。公共乘用车充电POI不得直接当重卡站。

V1不处理已有充电站的沉没成本与剩余可用容量。取得此类数据后需增加明确的已有设施机制，而不是把现有站成本悄悄设零。

### 3. 运输任务

最优资料是脱敏订单或运单：起终点设施、出发与完成时间、车辆类别、任务是否连续、载荷或有依据的能耗工况。GPS是识别路线和停留的补充，不是唯一入口。

如果拿不到订单，允许依据公开资料设计低、中、高等情景，但各数量与时序都要标为模拟并记录生成依据。城市货运吨数不能直接变成城市间OD或车次，货运企业数量也不能直接变成发车频率。

本版一行任务代表一辆独立分配车辆的一次行程。若有同一辆车的多段作业，必须另做任务链模型；不能按本版接口拆开后让每段重新满电。

### 4. 技术与成本参数

选定一类有资料支持的车型。能耗对应载荷和工况；电池额定容量、安全可用范围及有效充电能力分开记。文献参数的年份和地区要保留。

设备、土地和施工投资需要清楚范围；单价不含施工不能当建站总价。年化系数与运营天数要有依据，不能混加一天运营与多年资本。

## 三、建议的构建顺序和每一步产物

1. **来源确认。**重新获得有效原始文件或原始下载地址。保留文件、SHA-256、下载日期、来源和许可；错误页不进入正式表。
2. **小范围空间核查。**在广州、东莞、深圳地理框架下选一小批能逐条核查的设施，先完成节点和连接道路。不要先定必须覆盖全部行政区域。
3. **场站与路线核查。**记录真实入口/出口，比较合规路线；没有资料的项保持未核实，不填写想当然数值。
4. **充电必要性检查。**根据合理初始电量、真实距离与能耗检查途中是否需要充电。如果不需要，模型允许零建站；不能为制造需求强行降低电池。
5. **运输任务。**优先少量有授权的真实任务；拿不到则设为情景研究，记录生成规则、随机设置及不确定项。
6. **参数来源表。**确认车辆、成本、设备和时隙精度，标明实测、文献引用、推导或模拟。
7. **生成模型输入。**按CONTRACT.md逐字段整理，经校验后生成独立的research输入，不覆盖demo。
8. **小规模复核后扩展。**先人工核算若干路径；再测试更多任务、更多路径和更细时隙，并保存运行时间、gap及验证结果。

## 四、当前接口关键字段

完整、大小写敏感的接口见 `CONTRACT.md`。以下是用途解释：

| 表 | 关键字段 | 单位与意义 |
|---|---|---|
| nodes | node_id, label, source_id | 抽象网络节点，来源必须登记 |
| edges | edge_id, from_node, to_node, distance_km, travel_minutes, source_id | 有向路段、公里与分钟；不自动添加反向边 |
| sites | site_id, node_id, max_bays, charger_kw, site_power_kw | 可配置位数、每位功率、场站总功率上限 |
| sites | fixed_cost_cny, bay_cost_cny, open_slot, close_slot, source_id | 建站成本、单个位成本、营业时隙 |
| jobs | job_id, origin, destination, departure_slot, deadline_slot | 一次独立任务；最后期限允许等号 |
| jobs | initial_kwh, terminal_minimum_kwh, source_id | 出发电量和结束最低电量，不自动置满 |
| vehicle | battery_kwh, minimum_kwh, consumption_kwh_per_km, charge_efficiency | 容量、安全下限、单位能耗、效率 |
| settings | slot_minutes, horizon_slots, max_paths_per_job, max_plans_per_job | 离散时间和有限方案规模限制 |
| settings | annualization_factor, operating_days_per_year | 资本年化和典型日转年度系数 |

商业或个人信息应在进入共享项目之前脱敏。真实轨迹与企业数据是否允许公开，需要单独确认，不能因为用于学术论文就默认可上传。

## 五、向老师提出的最小数据请求

> 我已完成抽象算例与基础模型，现在需要把输入替换为有依据的货运场景。是否能提供或介绍渠道获取一小批脱敏运输任务，包括起终点设施、时间要求和车型？另外希望核实一类车辆的能耗与充电参数，以及若干场站是否允许重卡进入、可用充电位数量与成本范围。没有完整GPS也可以先从运单或实际作业规则开始。

若仍拿不到真实任务，论文必须保持“公开地理网络上的参数化情景规划”，不写“真实广东需求估计”。
