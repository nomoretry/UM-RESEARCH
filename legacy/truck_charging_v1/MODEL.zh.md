# 初步数学模型与代码对应

## 1. 问题

给定有向运输网络、若干备选充电场站和独立运输任务，同时决定建站位置、充电位数量与各任务的路线和充电安排，使年化建设成本与年度运营成本之和最小。所有任务必须服务；不通过删除任务或设置随意罚金掩盖无解。

这是有限方案集的混合整数线性规划，不是完整道路网络上的全局路径搜索，不是需求估计，也不是电网规划。

## 2. 先生成单车可行方案

对任务k，构建路线与充电安排集合R_k。每个方案包括有向路段、到站时间、充电开始结束时间、逐段电量和完成时间。

电量递推为：

\[
E_{next}=E_{current}-e\,d+\eta P\Delta t.
\]

这里d是行驶距离，e是单位里程能耗，P是充电设备从电源侧取用的功率，η是充电效率。没有充电的路段，充电项为0。每段行驶后电量不得低于安全下限；充电后不得超过电池容量；结束电量满足任务要求。

V1先用NetworkX按距离生成前K条简单有向路径，再枚举中途场站的整时隙充电与等待。没有充电需要时允许直接通过，不强迫建站。达到方案数量上限会明确报错，而不是偷偷截断。

代码对应：`truckplan/plans.py`。

## 3. 决策变量

- y_s∈{0,1}：是否建设站点s。
- n_s为非负整数：站点s配置多少充电位。
- x_kr∈{0,1}：任务k是否选择方案r。

## 4. 目标函数

\[
\min\; a\sum_s(F_s y_s+C_s n_s)+D\sum_k\sum_{r\in R_k}c_{kr}x_{kr}.
\]

a是年化系数，D是每年使用该典型日模式的天数，F是站点固定投资，C是单个充电位投资。

方案运营成本为：

\[
c_{kr}=c_{km}d_{kr}+p_e(e\,d_{kr}/\eta)+c_h T_{kr}.
\]

T包括行驶、充电和在站等待的累计时间。电价在本版各时刻和地点相同，能量成本按实际行驶耗能折算；这避免只计算途中购电而忽略出发电量的消耗成本。它不是时空电价套利模型。

## 5. 主要约束

每项任务选择一个方案：

\[
\sum_{r\in R_k}x_{kr}=1,\quad\forall k.
\]

只可使用已建站点：若方案r在s充电，则x_kr≤y_s。

建站与充电位联动：

\[
y_s\le n_s\le \bar n_s y_s.
\]

令A_krst表示方案r在时隙t是否占用站点s的一个充电位：

\[
\sum_{k,r}A_{krst}x_{kr}\le n_s.
\]

充电位占用采用左闭右开区间[start,end)，上一车结束的时隙边界允许下一车开始。

站点功率约束：

\[
P_s\sum_{k,r}A_{krst}x_{kr}\le \bar P_s y_s.
\]

这只是给定功率限制，不需要潮流模型。单车续航、时间窗和开放时间已在方案生成阶段检查，选址模型只选择有效方案。

代码对应：`truckplan/model.py`，SciPy `milp`调用HiGHS。

## 6. 求解之后独立验证

`truckplan/verify.py`重新读取原始有向边、车辆参数和充电事件，逐段重算时间与电量，不信任方案文件中预计算的汇总值。随后检查任务是否恰好服务一次、站点是否建设、充电位与站功率是否超限，并重新核算年度目标。

求解器找到最优解与独立验证通过是两个不同结论。若达到求解时限但仍有可行解，记录`feasible_limit`和gap，不能写已求得最优。无解也仅说明当前离散化和路线集合无解，不能推断现实中绝无可行路径。

## 7. 怎么判断模型有用

当前六组算例是代码测试，而非论文验证。进入研究阶段后，至少需要：

1. 核实地理节点、出入口和任务；独立检查路线与时间。
2. 改变时隙长度、K条路径数量，检验最优布局是否稳定。
3. 设置“先选址再选路线”等有意义且可行的基准。
4. 使用独立任务情景评价方案，不只在用于规划的任务上报结果。
5. 查清场站接入问题的近邻文献；若增量已被充分覆盖，不将它宣称首创。

当前还没有完成这些研究层面的验证。
