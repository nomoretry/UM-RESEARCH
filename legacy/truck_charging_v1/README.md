# 电动重卡充电选址与路径优化：可运行初版

## 当前完成到哪里

本项目用于把研究计划落实为可运行的数据接口与数学模型。首版是用户批准的**抽象模拟验证算例**，不是广州、东莞、深圳的实测研究数据，也不是可直接投稿的实证结果。

已完成：

- 原有 `stations_public.parquet` 文件审计。它实际是146字节的403错误网页，不能作为数据导入；原件没有修改。
- 一套明确标注为测试数据的JSON输入：4个抽象节点、5条有向路段、2个备选站点、2项独立运输任务。
- 有限路径与充电安排生成、选址与充电位配置MILP、独立的物理约束和成本校验。
- 正常需求、不需充电、功率受限、容量导致无解、道路接入方向变化、服务约束放松六种测试。
- 有原文页码的文献参数参考表。该表不会自动覆盖模型参数。

本次验证：106项自动化测试通过；小规模穷举与MILP最优值一致。这里的自动化测试数量不是研究样本量，也不等于模型已通过真实业务验证。

尚未完成：三城真实物流节点和路网、核实后的重卡站点出入口、真实OD及运营数据、地域参数校准、论文创新性验证。

## 第一次运行

本机项目已建立独立 `.venv`，不改动系统Python。PowerShell进入本文件所在目录后：

```powershell
.\.venv\Scripts\python.exe run.py --scenario all
.\.venv\Scripts\python.exe -m pytest -q
```

只跑基础算例：

```powershell
.\.venv\Scripts\python.exe run.py --scenario base
```

使用自己整理且通过格式校验的数据：

```powershell
.\.venv\Scripts\python.exe run.py --data data/research/model_input.json --scenario base --output results/research_run
```

上面的 `data/research/model_input.json` 是未来完成整理后由你指定的输入位置，**目前没有该真实数据文件**。不要直接把采集清单或错误下载改名放进去。

迁移到其他机器：使用Python 3.12创建本地虚拟环境，再安装 `requirements.txt`。保存同一份输入文件；不要期望多解问题每次返回完全相同的方案编号，应该比较目标值和可行性。

## 先看哪些文件

1. `MODEL.zh.md`：模型要解决什么、数学式子和现阶段边界。
2. `DATASET.zh.md`：真实数据怎样分批构建、哪些字段必须核实。
3. `data/synthetic/demo.json`：当前实际运行的测试数据；所有数值都是测试设置。
4. `results/RESULTS.zh.md`：六组测试的中文结果摘要；机器可读版本为`results/comparison.json`。
5. `results/base/selected_plans.json`：模型选择的路线与充电时间。
6. `results/base/verification.json`：逐段重新计算电量、时间和成本后的校验。
7. `data/reference/literature_parameters.json`：文献参考参数与不宜直接照搬的条件。
8. `results/source_audit.json`：原始文件为何被拒绝的审计记录。

每组结果同时保存 `input.json`、完整方案集合、求解结果、独立校验、环境版本与输入SHA-256。输出文件由程序生成，调整应从输入或源代码开始，不能手动修改结果充当新实验。

## 测试结果怎样解释

基础输入下，车辆沿 O-A-D 行驶，先行驶80公里，抵达A时电量从160降至80 kWh；充电一小时补入60 kWh，再行驶120公里，最终剩20 kWh。两个任务同时到站，完整模型配置两个充电位。

年度目标46.2万元由年化投资1.2万元和年度运营45万元组成。这里所有里程、成本、参数和运行天数均为测试设置，**不能引用成真实建站成本、节约比例或广东规划建议**。

服务约束放松模型得到46.1万元，但只建一个充电位，安排两辆车同时使用，因此独立校验不通过。该结果只用来检查程序是否能识别不合理方案，不是论文所需的强基准。

## 已知边界

- 每个任务是一辆已经分配好的车的一次行程，不做车队派单、串联任务或需求预测。
- 初版不在起终点充电；初始及最低结束电量必须给定。连续任务不能直接复制成相互独立的满电任务。
- 每个任务只使用前K条按距离排序的简单有向路径。最优与无解都仅针对当前路径及充电方案集合；K太小会遗漏有价值路线。
- 行驶时间按每条输入路段分别向上取整到时隙；充电持续完整时隙。演示采用60分钟，精度很粗，不适合直接用于实证；缩小到15或30分钟会增加方案数，需测试精度与运行时间。
- 充电采用单车型、有效兼容功率和常效率简化，不建非线性快充曲线。
- 等待只用于调度充电；没有站内排队车道容量或随机排队模型。
- 站点功率上限是输入，不是电网潮流或真实接入可行性证明。充电位与功率约束分开处理。
- 运营电费按行驶消耗的能量和统一效率折算，包含起始电量消耗的成本，不是逐站账单结算模型；未使用到达剩余电量的任意套利收益。
- 同一个典型日乘全年运营天数是简化，不代表日间需求差异。
- 所有位置均为新建设施选项，暂不处理已有设施、外部用户占用、扩建、碳排放与多阶段投资。
